主线程范围为 NewFrame 前至 RenderDrawData 返回；Present 和完整帧间隔另列。所有最大长尾与完整帧缺口保留，没有另外虚构完整帧间隔硬阈值。正式阶段确认遮挡／最小化即判该轮覆盖不足，不暂停墙钟凑时长。

自动操作是夹具直接调用生产入口到效果确认、首个提交帧的延迟，包含调度和确认；不是鼠标输入延迟。七类为切换、逐 PID 配置、筛选、滚动、详情、清空与导出启动。清空后在同一个已计量主线程帧恢复该段 5000 条结构化历史，恢复成本保留在操作与帧中；每帧检查控制负载不低于 10000。末尾 2.4 秒停止发新操作，完整 120 秒继续渲染／接收；结束后的 200 ms finalizing 与最终 drain 不混入正式预算。

微基准与合成源复用生产 Hook 翻译单元，未复制 Hook／Store 算法。定时合成源用 S_OK/S_FALSE 并编码独立源行号；有意失败由既有确定性跨进程探针验证，不冒称压力场景覆盖了 API 失败。GUI 托管合成场景通过真实注入／controller 握手，但调用负载来自探针内生产 Hook 入口；它不是真实音频。独立停收探针不带 GUI，GUI 连续出帧由单独的 GUI 过载轮证明。

1024 窗口保存最近收到的记录。生产读取器扫描 64 个物理槽，接收顺序不等于全局源调用顺序；逐条核独立源行号与结果、最终源推进及最后扫描范围，另列与源顺序最后 1024 行的边界差异，不通过偷偷排序改写窗口语义。源覆盖、拒写、controller 丢弃、探针丢样、音频不连续分别统计。

音频仅计循环体，周期控制调用和 Sleep 在计时范围外。性能子目标创建前即进入独立预热桶；循环 start QPC 属于正式边界才计入正式组，跨结束边界的在途循环完整保留并单列。静音 render 证明原调用和音频帧推进，不证明有声内容质量。

音频格式一致性按实际保存的 endpoint／rate／channels／bits／validBits／channelMask／formatTag／bufferFrames／Sleep 字段核对。`HookAudioProbe.cpp` 的 `victim` 只调用一次输出端 `GetMixFormat(&format)`，同一个 `format` 指针依次用于 `Initialize/render` 和 `Initialize/capture`，之后才释放；同一次四态配对复用相同两个已启动目标，不重新初始化、不切换格式。元数据没有保存 `WAVEFORMATEXTENSIBLE.SubFormat` GUID，因此不把 tag=65534 擅称为已经逐轮核验 Float/PCM GUID 相同；这项历史字段未覆盖，不能用事后的当前设备查询回填。
