# 单目标后台附加实施与验证（#256）

本票把现有单 PID 附加入口改为后台安装，并使既有目标的接收、配置和分离不再等待另一个目标安装。未修改 Hook 协议、安装超时、历史轮次、默认监控选择及启动观测边界。

## 线程与所有权

- GUI 只发送附加、分离和 pump 配置命令，逐帧消费拥有型结果／批次；`CallLogStore` 仍由 GUI 独占，借用 `View` 不传给后台线程。
- 一个安装线程准备未提交的 `OnDemandAttach`。准备结果通过容量为 1 的拥有型交接槽移动给接收线程；发送方此后不再访问附加对象。
- 一个接收线程独占 `PipelineAttachSet` 及其中所有活动对象，负责 drain、配置、目标退出检测和 stop。安装线程等待远程加载／Hook 安装时，该线程继续推进。
- 取消与成功提交共用同一把控制锁，明确先后顺序。取消先发生时禁止提交；成功先提交后收到分离命令时，由接收线程结束该活动对象。失败和取消不结束已有目标，不清除 GUI 已有记录。
- 安装超时、迟到完成和未结束的远程资源继续使用 #253 的托管。接收线程维护待收尾数；工具关闭显式取消并回收本地工作线程，然后才进入前端日志与全局对象收尾。不终止既有目标。

## 容量与过载

一次只准备一个新目标。交接槽容量为 1；分离命令队列与拥有型结果／接收批次队列各最多 32 项；控制器活动目标上限为 64，同时仍受原有附加资源准入上限约束。pump 配置只保留最新期望值。

结果队列满时，接收线程继续 drain 来源，对无法交给 GUI 的调用累计缺失条数、对跳过的接收快照累计批次数；生命周期结果保留，待 GUI 消费出空间后提交。分离命令队列满时返回拒绝并累计拒绝数。GUI 显示准备中、待收尾和队列缺失／拒绝；不把缺失算成零调用。

## 测试边界与证据

测试通过生产控制入口、真实目标进程、真实 DLL 加载和既有 `RemoteInjectionGate` 验证。第一条回归先保留原同步路径，在真实 loader gate 未释放时确认命令入口 150 ms 内不能返回，日志明确失败；再改成后台控制器后通过。证据位于 `.scratch/implement-pipeline-2026-11-02/256/red-debug.log` 和后续测试 XML／日志。

硬件无关的真实进程场景覆盖：正常提交、单目标重复分离、目标退出、安装拒绝而既有目标继续活动、有界队列过载、重复取消、迟到安装托管，以及工具关闭。独立双目标场景验证 A 已活动且持续收到至少三批拥有型快照时，B 真实安装仍等待门控；A 已完成单独分离后，B 仍 pending、门仍未释放、两个目标仍存活。此场景只证明状态与接收调度，真实音频调用序列和生产 GUI 响应须另列现场证据。

相关旧二进制基线 Debug／Release 各 22 例通过。最终 Debug／Release 各 78 例通过，退出码均为 0；过滤器与退出码保存在 `final-*-result.json`，XML 和完整日志同目录。只运行与本票直接相关的控制、附加、最近调用窗口、记录存储、导出及文案测试；不将此结果称为全量回归。

构建使用现有 `Visual Studio 18 2026` 的 `build` 缓存，未改本机 preset 或 CI 工具链。期间一次 Debug 增量构建因人工验证正在运行 `RemoteInjectionTarget.exe` 被 `LNK1168` 拒绝，保留原日志，待夹具退出后重新构建；不把此失败计作产品行为失败或通过。

## 真实音频双目标

手动探针仅存于上述证据目录的 `audio-probe/`，通过包含原 `HookAudioProbe.cpp` 并重命名其入口复用现有音频目标，不复制音频循环或另造接收算法。探针调用生产 `PipelineAttachController` 和 `CallLogStore`；B 使用原真实 loader gate。

Debug 实测 A PID 28548、B PID 30072：B 安装命令耗时 0 ms；B 安装仍 pending、门保持关闭时，A 连续收到四组 `GetBufferSize(frames=4800)`、`GetService(IAudioRenderClient)`、`GetService(IAudioCaptureClient)`，12 条均为 `S_OK`。B 发起后第 1234 ms，A 已完成分离（命令至结果 16 ms），B 仍 pending 且门仍关闭，两个目标均存活。A 的音频回调继续增长至 110 次、失败数为 0，已接收的 15 条记录全部保留。随后取消 B、释放门并确认托管回收；A、B 真实退出码均为 0。完整逐条方法、参数、时间和结果见 `audio-probe-run.log`，最终 `result=PASS`、探针退出码为 0。

## 生产 GUI

现场第一轮已取得 B 准备中截图（记录数 525）、超时待收尾截图（记录数 801）和可点击的失败筛选；A 在 B 安装等待窗口持续执行上述三方法且音频失败为 0。人工桌面操作未在 10 秒安装等待内完成 A 分离，因此这轮截图不作为同窗单 PID 分离的证明；该项由前述精确计时的真实音频探针补充。

这一轮 B 因测试 gate 自身等待到期退出 6，不能作为正常收尾通过。GUI 关闭时也实际复现了工作线程晚于函数静态托管存储析构的竞态，CDB 栈保存在 `gui-close-hang-cdb.log`；随后加入显式 `shutdown()`，先取消／回收工作线程，再关闭日志和全局状态。

修复后重新启动正式 Debug GUI（PID 25912），二进制哈希保存在 `gui-final/binary-hashes.json`。附加真实音频目标 A（PID 18796）后，界面显示 `GetBufferSize(frames=4800)`、两个 `GetService` 及 `S_OK`，截图见 `gui-final/a-attached.png`。正常关闭窗口后，独立句柄等待器确认 GUI 真实退出码为 0，见 `gui-final/gui-exit.json`；其中等待时间包含关闭操作前的人工等待，不能解释为关闭耗时。
