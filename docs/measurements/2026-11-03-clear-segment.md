## 行为

活动段清空走既有接收器命令队列；身份、协议、目标存活和代次上限校验全部通过后，先准备新代接收起点，再原子发布相同 API 选择与新代次。只有成功结果才能清主进程数据。记录与源端快照均携带观测代次；旧在途、共享传输和控制器队列中的旧代数据不能填回新段窗口或累计。

发布失败保留原记录、最近窗口、累计和起点。协议或实例不能核验时，不用不可验证的零快照覆盖最后可验证统计。代次耗尽明确失败，不回绕。成功清空保持原 API 选择和同实例配置记忆；原先无法确认的传输覆盖仍表达为未知。

结束段本地清空，不接触已退出进程；身份、结束状态和最后结束时点仍在。控制记录身份独立于容器位置，因此清空一个段不更改其他段的详情身份。清空同步失效查询、接口、Initialize 图贡献和最近窗口缓存；已有拥有型冻结记录仍可读。
