## 生产协议

布局从 8 升到 9，映射名包含布局号，另核对布局字段、字节数、进程创建时间及实际已载 DLL 的内容身份。旧布局／不同内容 Hook 明确拒绝并要求重启；同实例重附加复用映射，不清空仍有旧写者可能访问的存储。观测代次耗尽仍按既有规则拒绝重附加，不允许自然回绕进入另一段。

每条调用先取得 64 位传输预留序号，再对对应槽做一次独占 CAS。槽的四种状态是 Empty、Writing、Ready、Reading，所有权同时携带观测代次。

1. 写者只能从 Empty 或 Ready 取得 Writing。碰到占用或 CAS 失败立即放弃本条，不等待接收方。
2. 取得所有权后复核当前观测代次及该槽最后的序号。过时预留即使晚于新记录取得槽，也不能覆盖新记录；64 位序号按有界距离处理正常回绕。
3. 写者独占期间复制完整载荷和序号，最后通过原子操作发布 Ready。读者不能仅凭预留索引增加判断记录完成。
4. 读者只能从 Ready 取得 Reading，独占复制后释放为 Empty。目标写者不会覆盖正在复制的载荷；读者也不与普通结构写入并发访问。未取得所有权的一方不访问载荷。
5. 覆盖同代、尚未被取走的 Ready 记录才增加已知覆盖数。覆盖旧段记录不计到新段。已完成接收的槽为空，不会再次被算作丢失。

目标路径使用固定存储、原子操作和栈上对象，没有堆分配、阻塞锁、文件 I/O 或等待 GUI。槽位独占只有一次 CAS；损失计数最多尝试 8 次 CAS，仍失败即置未知并返回，不做无界重试。

损失计数用一个 64 位原子量同时保存 32 位观测代次和 32 位数量。更新以原子方法配置中的当前代次为权威，旧调用不能把计数切回旧代；数量回绕或有界更新失败会保留未知，不能把数字当作精确总数。未知提示不会替换成“零缺失”。

接收线程每轮每 PID 最多检查 256 个控制槽及 64 个高频槽；停止时控制通道最多再检查完整 2048 槽一次，不等待目标调用完成。目标数上限 64，中间批次队列上限 32。GUI 消费停止时仍轮转所有活动 PID，队列丢弃按完整实例和段 token 归属。结束结果只在有输出空间时处理，有限收尾和缺失快照先入同一批次，再归档；旧批次和迟到状态不能修改已归档段。

`PipelineAttachController → SegmentSelection → CallLogStore → AppUi` 已接通真实逐段状态。高频中间消息改为唯一接收增量，Store 在既有 64 条范围内合并；窗口淘汰、API 失败和音频不连续均不进入上述传输缺失数。
