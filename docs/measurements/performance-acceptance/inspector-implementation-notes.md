# Inspector 实施取舍记录

本文件记录 #225～#228 的常规实现取舍，不替代 #219 的范围和验收。正式优化前基线全部完成后才修改生产 Inspector 路径。下方分票结果保留当时阶段状态；最终本地测试、真实 GUI 和性能验收已完成，见 [实施记录](implementation-log.md)、[Inspector 后测](inspector-acceptance-report.md) 和 [GUI 行为记录](gui-checks/README.md)。

## 单份记录与身份

采用拥有型不可变记录引用。控制内容只移动入库一次，排序、匹配、图贡献和导出只保存引用或索引。Store 在 GUI 线程访问，导出线程只读冻结的引用集合，因此 Store 不需要在写盘时加锁。

记录身份保留 round、Attach 段、lane 和逻辑 sequence。控制 sequence 用接收顺序，显示排序使用 timeMs 后接收序。Attach 集合按 PID 升序 drain；同 PID 重连分配新段。不能用 GUI 行号、PID 或共享环槽号代替记录身份。

现有 CallLogFilter 是纯 C++ 头文件，位于 gui。Store 接管查询后将它移到 core，沿用同一匹配实现和原测试，避免在 core 依赖 GUI 或复制一套近似规则。

## 查询和近期 pump

首批缓存全量轻量控制排序索引和当前查询的匹配索引。仅新增控制批次或查询变化时重建对应部分；不实施增量排序。参数内容不进入第二份展示容器。

pump 仍有界轮询，不以 pumpWriteIndex 未变化为理由停止读槽。新 Attach 记录起始边界；计数回退或无法证明连续时失效旧身份。现有协议先递增计数再写槽，不能据此宣称新增严格发布保证或无损交付。

适配器在 Attach 开始记录计数和既有槽内容，排除开始前的逻辑位置及尚未被新内容替换的旧槽。每次最多检查近期窗口，计数不变也比较槽内容，因此先预留后写完的记录可以在后续轮询出现。槽复用、同位置内容改变或计数回退不能复用已经公开的 record 身份；回退时清除无法证明连续的近期窗口，后续从新边界继续。必要的稳定内容比较只改善观察，不把本地版本号当远端发布确认。

最终最多 64 条 pump 通过二分找到在控制查询索引中的插入位置。逻辑行按位置映射到控制或 pump，不每帧构造 N+64 的完整向量。控制选择可借助当前查询的反向位置索引定位，避免 pump 更新时为选择而扫描整份控制历史。

## 图摘要

每个 Attach 段只收集 Initialize、InitializeSharedAudioStream 和 SetClientProperties 的轻量贡献引用。相关版本变化才按原稳定顺序提取，保留同 PID 活动／最近段、primary stream 和 false／HRESULT 0 的语义。普通调用只更新计数。

图仍由现有 assemblePipeline 构建，使用缓存 Hooked hint 与 ETW 的既有合并规则。不增加平行图构建器；只有有效图输入变化才重建节点。

图节点缓存比较 session、endpoint、合并后的 Initialize hint 和 probe 的实际值，再调用原 assemblePipeline。缓存仅持这四组小型输入及既有节点，不保存调用参数树；来源条数和 stream 提示独立更新。音量／静音的 Live session patch 同样进入此比较，避免缓存后图参数停留在旧值。

## 保存和轮次替换

录制状态区分从未建立范围、跟随和冻结。冻结为空时明确返回空，不回退历史。保存只捕获引用和接收边界，按接收顺序逐条序列化。

导出使用一个专用线程和窄文件写出边界，以确定性测试制造阻塞及各阶段失败。同目录临时文件完成 write、flush、close 后再以不覆盖方式发布；取消或失败清理临时文件，清理失败明确保留未完成状态。

文件写出边界只暴露 open、write、flush、close、publish、cleanup；生产实现负责本次临时文件，测试实现用条件变量控制阻塞及逐步失败，不引入通用线程池或文件框架。任务在 take 回收结果和 join 前始终算忙，完成标记采用 release／acquire 交接，后台不访问 Store 或 ImGui。默认文件名由冻结来源与唯一后缀产生；指定路径也使用不覆盖发布。

全部 Detach 后替换旧轮前显示保存条数及将放弃的总数，并提供保存、放弃、取消。只有用户完成保存或明确放弃，并且新 Attach 实际成功，才清理旧轮。后台任务忙时不排队替换。正常退出持续处理消息，等待或取消后回收线程。

录制状态按三态实现：未建立范围、跟随当前接收上界、冻结接收上界。关闭到开启时纳入当时全部历史；开启到关闭时只存上界，不复制内容；新轮在开关关闭时回到未建立范围，在开启时继续跟随。显式冻结的零上界与未建立范围必须区分。

替换确认固定请求的 PID 和来源提示，不能在保存结束时改用已经变化的焦点。保存失败或取消保留旧轮；选择放弃也只授权提交替换，不能在实际 Attach 成功前清除旧轮。保存按钮已有任务时只显示忙；替换对话框明确发起的“保存后继续”才允许在保存成功后继续该请求。

正常关闭请求先交给界面处理。后台写出未结束时保留消息循环和窗口，提供等待或取消。正常可见帧在 beginFrame 后回收结果，将完成通知和后续界面工作计入主线程；窗口遮挡时只回收线程并暂存结果，恢复显示后再处理通知。销毁前最终回收线程，不能靠 detach 线程或提前释放来源退出。

图输入可以直接将 Store 提取的 Hooked hint 与 ETW 按已有规则合并，再交给同一个 assemblePipeline；现有函数在未传调用列表时已经接收完整 hint。无需复制参数树，也无需第二套图构建器。全量参考测试仍使用原 HookedCall 提取和 assemblePipeline 入口。

## 验证边界

计量继续保留接收、排序、匹配、图摘要和保存启动的不同阶段；Store 不依赖 GUI 头文件。优先使用窄阶段观察回调连接 FrameProbe，并同时暴露实际处理条数和当前容量；不为计量搬动整个模块，也不把嵌套阶段耗时直接相加。

新近期窗口适配器会遇到残缺共享槽，读取字符串必须受固定数组长度约束，参数 blob 长度不能超过实际数组。参数解码拒绝不完整字段，不将半条参数树作为成功结果。这里只补读取边界，不修改 Hook 发布顺序或布局。

控制选择直接按接收 sequence 查找不可变记录；排序与匹配保存索引，参数面板不绑定行号。主表显示用的单行摘要只为当前绘制行生成，原始净化摘要与参数树仍由记录拥有。查询只保留当前一组，不积累历史查询缓存。

先运行可失败的行为回归，再改生产路径。Store、生产纹理持有至 WARP、文件写出边界分别验证确定性行为；正式 GUI 性能采样与编译隔离。固定数据、真实十分钟会话和真实驱动图表证据分别记录，不能互相替代。

当前真实连续目标在 Attach 前已经 Initialize，之后主要产生 GetBufferSize／GetService 等低频控制调用。十分钟会话可以证明持续接收、真实来源、pump 与内存趋势，不能自动证明重新 Initialize 或图字段覆盖；这些语义还需要固定数据对照和独立的短生命周期检查。

## 接线顺序与可复核边界

1. 先在现有 CallLogStore 入口验证录制三态和冻结引用，替换 RecordingGatesAppend 的旧语义测试：关闭录制仍接收，保存范围单独决定。再增加轮次／Attach 段、同 PID 重连及引用跨追加存活的行为回归。
2. Attach 适配器只补近期窗口观察身份，不改变共享结构布局和发布顺序。读槽使用固定长度字符串及受限参数 blob；有界内容比较不能充当远端发布确认。先增后写的槽在计数不变时仍需能出现。
3. 生产接收只移动一次；GUI 主表、图提取及同步过渡保存均改读不可变引用，移除 pipelineCalls_ 和录制内容副本。第一批可暂时每帧整理轻量引用，但不留第二份参数树；下一票再缓存索引和裁剪。
4. 替换请求保存固定 PID、device／flow 和来源提示；确认期间焦点变化不能改变目标。保存或明确放弃只授权尝试，成功 Attach 之后才 beginRound。忙状态从第一批即参与保护，后台任务票再接真实 busy。
5. #226 仅在控制新增或查询编辑时重建对应索引。pump-only 小窗口合并及反向位置表分开失效；UI 行高随当前字体和 cell padding 计算，不缓存全量行布局。
6. #227 沿用 HookedCall 的同一提取规则，新增借用记录入口以避免参数树复制。摘要与图节点分别判变，计数变化不重建节点；迟到贡献与稳定全量参考比较。
7. #228 将过渡同步保存替换成单任务工作线程。文件步骤通过专用写出边界验证，UI 正常关闭请求不直接 PostQuit；可见帧内回收和处理完成结果，遮挡分支只回收并暂存，窗口持续响应至线程结束。

确定性验证和性能验收分开。固定数据生成／序列化内容保持原哈希，身份字段只加入实际导出记录；测试夹具不通过减少参数树或改变字符串长度降低负载。每票收齐直接测试与构建后单独本地提交，最终再跑全套和双轴评审。

## 待执行的行为验证顺序

下表是实施入口和独立期望，不是已通过的结果。测试边界沿用规格已经确认的 Store、Attach UI 模型、真实共享 Ring 读取、图提取和文件写出入口，不另要求选择测试边界。

| 顺序 | 入口 | 独立期望 |
| --- | --- | --- |
| 1 | CallLogStore 接收与录制 | 关闭录制收到 A；开启收到 B；关闭收到 C，历史为 A／B／C，冻结导出只有 A／B；再开纳入三条 |

## #225 本地接线结果

控制接收已移入单份不可变 Store，生产路径移除 pipelineCalls_ 及录制内容副本。主表暂只复制轻量引用；排序、筛选和图摘要的重复工作留给后续两票。替换成功后才提交新轮，失败／取消保留旧轮；pump 选择失效时清除并提示。PerformanceFixture 使用同一 recordId，固定输入序列化保持不变。

Release GUI、性能 GUI 和测试目标构建通过；54 项 Store／HookedCall／参数／Attach／图直接测试通过，结果在 build/performance-vs18/inspector-source-final-green.xml。红证据另见 inspector-history-red.xml、inspector-range-red.xml 和 pump-reuse-red.xml。完整 Debug／Release 与真实 GUI 多 PID／轮次演示将在各项集成后再收齐，不把本段局部测试当整线验收。

OnDemandAttach 的头文件只前置声明 PumpCall，PumpWindow 定义仅在 cpp 的 COM 公共头之后包含；曾直接包含造成 Windows GUID_NULL 宏与 COM 声明冲突，按现有 COM 包含顺序修正，没有修改公共 GUID 或增加兼容宏。

只读规范评审指出共享槽连续两次普通读取可能被优化器合并。两次快照之间补 MemoryBarrier，确保第二次重新读取；既有顺序测试不能证明跨进程并发完整发布，仍保留协议限制。此修正不改变共享结构或写入顺序，后续以生成代码及直接回归复核。

## #226 查询与可见行

Store 缓存当前查询的控制排序、匹配和反向位置索引，pump 只维护最多六十四条的二分插入位置。无新增不重排、不匹配；Iface 使用独立小列表。主表只提交裁剪范围，首次 Step 前包含定位选择；自动测量首行高度以包含当前字体、CellPadding 和 Selectable。Call 与 Args 仅显示时替换换行，提示与参数面板保留完整内容。

Release 三个目标构建通过，二十六项直接测试通过，见 inspector-query-green.xml。真实一万条短运行已完成，截图观察到旧／新记录定位和独立参数面板，尚不据此宣布完整性能或 DPI 验收。图摘要仍沿用全量参考，下一票消重。

## #227 摘要与图输入判变

每个 Attach 段仅追加三类字段贡献引用与控制计数；普通调用不保存第二份索引。initializeHint 按段缓存，含 legacy PID 0 时按时间／接收序合并贡献再提取，避免合并两个最终摘要丢失 primary stream 语义。sessionRecords 保留为全量参考入口，生产摘要不调用它。活动新段不借旧段，Detach 取最近段。

PipelineGraphCache 比较 Live session、endpoint、合并 hint 与 probe 的实际值后复用原图，状态计数独立更新；音量／静音通知也更新选中图。三十六项直接测试通过，红证据 inspector-hint-red-build.log 与 inspector-graph-red-build.log，绿结果 inspector-graph-final-green.xml。曾将测试字段误写为 Mute，按既有小写 mute 修正测试；未为测试改变产品字段。
